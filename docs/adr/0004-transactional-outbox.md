# ADR-0004: Transactional Outbox + один активный relay через advisory lock

**Статус:** принято

## Контекст
Dual write «закоммитить в Postgres, затем отправить в Kafka» теряет события при падении между
шагами, а «сначала Kafka» публикует изменения откатившихся транзакций.

## Решение
- Изменение доменных таблиц и вставка в `outbox` — одна транзакция (Unit of Work).
- `outbox-relay` в цикле: открывает транзакцию, берёт `pg_try_advisory_xact_lock`, читает пачку
  неопубликованных записей по возрастанию `id`, публикует в Kafka,
  дожидается ack'ов и помечает записи `published_at`.
- Replica'и relay'я — 2 (для быстрого failover), но advisory lock гарантирует, что публикует ровно одна:
  сохраняется порядок изменений по ключу.
- Если relay упал после отправки, но до коммита — записи переотправятся; для compacted-топика с
  upsert/tombstone семантикой это идемпотентно.

## Последствия
+ Нет потери и «фантомных» событий; не нужен Debezium/Kafka Connect для такого объёма.
− Polling раз в 500 мс; при больших объёмах — перейти на CDC (Debezium) без изменения контракта топика.
